# ピクセルスタイル仕様（daily-app Redesign）

参考画像の暖色トンマナを、ピクセルゲーム調に落とし込むための**再現可能な規則**。
新しい画面やコンポーネントを足すときは必ずこの規則に従う。

- Figma ファイル: [daily-app Redesign](https://www.figma.com/design/yp8EzSlzOom9KwycPKKSaD)
- Figma 変数コレクション: `daily-app / pixel`（モード名 `Pixel`）
- 参考画像: `docs/design-refs/tone-manner-design.png`
- コード側トークンの正本: `src/app/global.css`（§7 を参照）

## 1. 基準（これを外すとピクセル感が崩れる）

| 項目 | 値 | 理由 |
|---|---|---|
| **1アートピクセル** | **3px** | 画面上で1ドットに見える最小単位。全ての寸法はこの倍数 |
| **枠線** | **3px**（= 1アートピクセル） | 太さを混ぜない。2pxや1pxは使わない |
| **角丸** | **0**（例外なし） | ピクセルUIに丸みはない。丸くしたいときは階段状に切る |
| **余白の刻み** | **6px**（= 2アートピクセル） | 6/12/18/24/36/48。中間値を使わない |
| **画面サイズ** | 390 × 844 | iPhone 論理サイズ。390 = 130アートピクセル |
| **影** | 使わない | ぼかし影の代わりに「3pxずらした単色の矩形」 |
| **グラデーション** | 使わない | 色帯 + ディザリング（§4.2）で代替 |
| **blur / backdrop-filter** | 使わない | `docs/ai-dev-guide.md` §8.6 の iOS 制約とも一致 |

**この規則の副作用として、旧デザインのモバイル性能問題は構造的に消える。**
ピクセルアートは blur も滑らかなグラデーションも使わないため。

## 4. パーツの作り方

### 4.1 立体パネル（ベベル）

ピクセルUIの基本。光源は常に**左上**。

```
┌──────────────┐  ← 3px 輪郭 (ink/outline)
│▔▔▔▔▔▔▔▔▔▔▔▔│  ← 3px ハイライト (白 45% or 明色)
│              │  ← 面
│▁▁▁▁▁▁▁▁▁▁▁▁│  ← 3px シャドウ (accent-dark)
└──────────────┘
```

押下状態はハイライトとシャドウを**入れ替える**（へこんで見える）。

### 4.2 ディザリング（グラデーションの代替）

色帯の境界を6px市松模様でつなぐ。**上側の色**を下の帯に散らす。

- セルサイズ: 6px（= 2アートピクセル）
- 帯の高さ: 12px（2行）
- 実装: `(row + col) % 2 === 0` のセルを塗る

Figma では市松を65個の矩形にせず、**SVGとして1ノードでインポート**する
（`figma.createNodeFromSvg`）。コードでは `repeating-conic-gradient` または
インラインSVGの背景で再現できる（ランタイム blur なしを維持）。

### 4.3 スプライト

セル文字列から生成する。`x` が塗り、`.` が透明。

```js
const heart = [
  "..xx....xx..",
  ".xxxx..xxxx.",
  "xxxxxxxxxxxx",
  // ...
];
```

- セル 3px、12×10セル = 36×30px が標準サイズ
- 枠（`sprite/slot`）は 48×48px、`color/panel` 塗り + 3px 輪郭
- スプライトは枠の中央に配置（枠の左上 +6px）

### 4.4 セグメントバー（EXP / HP）

RPG のゲージは連続バーではなく**分割ブロック**で表現する。
ブロック 9px 幅 + 3px 間隔、枠は 3px 輪郭。

|---|---|---|---|
| **Vitality** | 体を動かす・活力 | `#d1564b`（HP赤） | `accent/rust` |

## 8. モーション

Figma の Motion（キーフレーム）で実装済み。**下の数値がそのまま実装の指定値**。

### 8.1 原則

| ルール | 理由 |
|---|---|
| **色の変化・出現・消失は必ず `HOLD`（補間しない）** | ピクセルアートに中間色は存在しない。フェードすると一気に安っぽくなる |
| 移動と拡縮は spring（`BOUNCY` / `EASE_OUT_BACK`） | 重さと弾みを出す。ピクセルゲームの手触りはここで決まる |
| 落下は `EASE_IN` で加速、着地は `EASE_OUT_BACK` | 引っ張られて落ち、枠にハマる感じを出す |
| 関連要素は時間差（stagger）で出す | 一斉に出すと情報の優先順位が消える |

### 8.2 ドラッグして達成（HOME画面 / 全体 1.5s）

| 対象 | プロパティ | キーフレーム（秒: 値, easing） |
|---|---|---|
| カード | `TRANSLATION_Y` | 0: 0 → 0.1: -12 `EASE_OUT` → 0.45: 220 `EASE_IN` → 0.58: **234** `EASE_OUT_BACK` |
| カード | `SCALE_XY` | 0: 1 → 0.1: 1.04 → 0.45: 0.46 `EASE_IN` → 0.58: 0.40 → 0.64: 0.34 `EASE_IN` |
| カード | `ROTATION` | 0: 0 → 0.1: 2 → 0.45: -5 `EASE_IN` → 0.58: 0 `EASE_OUT_BACK` |
| カード | `OPACITY` | 0.62: 1 → 0.66: 0 **`HOLD`** |
| 矢印 | `OPACITY` | 0: 1 → 0.28: 0 `EASE_IN` |
| 発光帯 ×2 | `SCALE_XY` | 0.56: 1 → 0.6: 1.06 → 0.84: 1.34 / 1.22 `EASE_OUT` → 1.0: 1 |
| 発光帯 ×2 | `OPACITY` | 0.56: 1 → 0.6: 1 `HOLD` → 0.84: 0 → 1.0: 1 |
| 枠の床 | `fills[0]` | 0.56: `#a06a14` → 0.6: `#ffd966` **`HOLD`** → 0.68: `#e8a52c` **`HOLD`** → 0.78: `#a06a14` **`HOLD`** |
| CLEAR! | `SCALE_XY` | 0.58: 1 → 0.68: 1.35 `EASE_OUT_BACK` → 0.9: 1 `BOUNCY` |
| EXP 10個目 | `fills[0]` | 0.82: `#14100a` → 0.88: `#e8a52c` **`HOLD`** |
| +10 XP | `OPACITY` | 0.6: 0 → 0.66: 1 **`HOLD`** → 1.1: 1 → 1.45: 0 `EASE_OUT` |
| +10 XP | `TRANSLATION_Y` | 0.66: 0 → 1.45: -72 `EASE_OUT` |

**移動距離 234px の根拠**: カード中心 (195, 362) → ドロップ枠中心 (195, 596)。
枠の高さ 88px に収めるため 0.4 倍（200 × 0.4 = 80px）まで縮小する。

### 8.3 達成エフェクト（FX画面 / 全体 2.4s）

| 対象 | プロパティ | キーフレーム |
|---|---|---|
| 集中線 | `SCALE_XY` | 0: 0.25 → 0.32: 1.12 `EASE_OUT` → 0.5: 1 |
| 集中線 | `ROTATION` | 0: 0 → 2.4: -9 `LINEAR`（ゆっくり回り続ける） |
| ラベル | `OPACITY` / `TRANSLATION_Y` | 0.06: 0 / -14 → 0.3: 1 / 0 `EASE_OUT` |
| CLEAR! | `SCALE_XY` | 0.1: 0.2 → 0.3: 1.3 `EASE_OUT` → 0.52: 1 `BOUNCY` |
| CLEAR! | `OPACITY` | 0.1: 0 → 0.14: 1 **`HOLD`** |
| カード | `SCALE_XY` | 0.24: 0.55 → 0.54: 1 `EASE_OUT_BACK` |
| スタンプ | `SCALE_XY` | 0.58: **2.4** → 0.7: 1 `EASE_IN` → 0.8: 1 `BOUNCY`（叩きつける） |
| ステータス行 ×4 | `OPACITY` / `TRANSLATION_X` | 0.86 / 0.90 / 0.98 / 1.02 から各 +0.2s で 0→1 / -18→0 |
| EXP 10個目 | `fills[0]` | 1.2 → 1.28: `#e8a52c` **`HOLD`** |
| 続行プロンプト | `OPACITY` | 1.78: 0 → 2.02: 1 → 2.26: 0（すべて **`HOLD`** で点滅） |

### 8.4 コード実装時の対応（framer-motion）

| Figma easing | framer-motion |
|---|---|
| `EASE_OUT_BACK` | `ease: [0.34, 1.56, 0.64, 1]` |
| `BOUNCY` | `type: "spring", stiffness: 300, damping: 12` |
| `EASE_IN` | `ease: [0.42, 0, 1, 1]` |
| `HOLD` | `ease: "steps(1, end)"` または該当時刻で値を直接切り替える |

**`HOLD` を安易に補間へ置き換えないこと。** ここがピクセル感の分かれ目になる。

| 画面 | eyebrow の色 | 見出し | 操作の文言 |
|---|---|---|---|

SpaceNavigator は廃止するが（`docs/ai-dev-guide.md` §5.1）、
**この関数の中身はそのまま移設して使える**。

### 9.6 DAYBREAK（日跨ぎの仕分け）

日を跨いだあと最初に開いた時に1回だけ出る（`docs/ai-product-brief.md` §4.6）。
Today の前の関門なので、**下部ナビを置かない**。

| 領域 | y |
|---|---|
| ステータスバー | 0–44 |
| `DAY 12 → DAY 13` | 60 |
| 「きのうの のこり」 | 84 |
| 「今日やるものを えらぼう」 | 120 |
| 帯の境界（ディザ） | 156–168 |
| のこり件数 | 180 |
| 仕分け行 | 210 から pitch 108 |
| 「今日をはじめる」 | 648–714 |
| 補足（あとで＝Overdue に残る） | 726 |

**文言は責めない。** 「終わらなかった」ではなく「のこり」、
「片付けろ」ではなく「えらぼう」。ブリーフ §3 の「目的は完璧な記録ではなく
継続と気づき」に合わせる（Overdue 画面の文言も同じ方針）。

**`TriageRow/Pixel`（354×96、Choice: Today / Later）**

| 位置 | 要素 |
|---|---|
| (3, 3) 12×90 | カテゴリ帯（左端） |
| (27, 14) | タイトル（body-jp） |
| (27, 36) | 所要時間・XP（caption-jp） |
| (27, 57) 153×30 | 「今日やる」 |
| (189, 57) 153×30 | 「あとで」 |

**面全体をカテゴリ色で塗らない。** 一覧の `CardRow/Pixel` は面を塗るが、
この行は上に二択ボタンが乗るため、彩度の高い面だとボタンが読みにくい。
左端の12px帯だけに留める。

## 9.7 レア度エフェクト（プリズム箔）

**ビックリマンのシール**が発想元。土台の絵は変えず、**表面の加工だけ**が
レベルに応じて豪華になる。

> **失敗した最初の案（2026-09-05）**: 参考画像
> （`docs/design-refs/ホログラムエフェクト.png`）の模様をそのまま再現しようとして、
> 24pxのセルを対角線で4分割した「ファセットタイル」を作った。結果は
> **ただのパステルの四角が並んだタイル**で、プリズムに見えなかった。
> **参考画像の模様を再現しようとしたのが誤り**。ホログラムの本質は
> 「見る角度で色が変わること」であって、あの市松模様そのものではない。

### 9.7.1 プリズムをピクセルで表現する6つの規則

滑らかな虹色グラデーションとピクセルは相性が悪い（エッジがぼやけて質感が浮く）。
**離散的な虹色配置**に置き換える。

**1. 斜めストライプの虹色帯**
- 虹色（赤→橙→黄→緑→水色→青→紫）を**45度の斜め帯**に配置する
- 帯幅は **2〜4ドット**。これより細いと単なるノイズに見える
- 45度なので `t = ax + ay`（アートピクセル座標の和）が同じ画素が1本の斜線になる
- 境界はぼかさない。**アンチエイリアス禁止**

**2. 境界のディザリング**
- 隣り合う帯の境目だけ、2色を市松に**1〜2ドット分**混ぜる
- 実装: 帯の先頭（`t % W === 0`）で `ax` の偶奇により隣の色を使う
- **広げすぎない。** 全体に散らすとノイズになる

**3. ハイライトの不規則配置**
- 白 / 明るい水色の 1〜2ドットを**ランダムに3〜6点**
- 密集させない。**角や縁の近く**に置くと反射感が出る
- 柄と一緒に動かさない（反射は面に貼り付いていない）

**4. 濃い縁取り**
- 虹色パーツの外周に濃い色（`ink/outline`）で1ドットの縁を入れる
- 背景と馴染みすぎるのを防ぎ、輪郭のはっきりした見た目を保つ

**5. パレットを絞る**
- 各色相**1階調**（`color/holo/1-red` 〜 `7-violet`）
- ハイライト2色（`hi` / `hi-cool`）＋ 縁取り1色 = **1要素あたり10色**
- 上限は12色。超えると「虹色のノイズ」になる

**6. 動きはコマ送り**
- 斜めストライプの位置を**1〜2ドットずつシフト**させると、
  「見る角度で色が変わる」質感が出る
- **4〜8コマで十分**。なめらかさより**コマ送り感**を残す
- 1周期 = `色数 × 帯幅` = 7 × 3 = **21アートピクセル（63px）**。
  ちょうど1周期送ると柄が元に戻るので、継ぎ目なくループできる

### 9.7.2 4段階

| Level | 加工 | 動き |
|---|---|---|
| **EASY** 5XP | **なし**（無地） | なし |
| **NORMAL** 10XP | **淡い箔**の枠（辺ごとに色相）＋ 四隅 6×6 ＋ ハイライト3点 | なし |
| **HARD** 20XP | ＋ スプライト枠の中が箔 ＋ ハイライト5点 | — |
| **EXTRA** 30XP | **放射プリズム（プラチナ）** ＋ 2ドットの太枠 ＋ **名前帯** ＋ ハイライト6点 | 光線が **2コマ**でコマ送り ＋ ハイライト明滅 |

**EASY は必ず無地にする。** 下限が素っ気ないほど上位が特別に見える。

**虹は HARD で「点灯」する。** NORMAL は彩度を落とした淡い箔（`color/holo/pastel-*`）に
留め、斜めストライプの虹は HARD 以上でだけ使う。こうすると4段階の差が
「無 → 淡 → 虹 → 虹＋動き」と明確になる。

**縞は要素をまたいで連続させる。** 配置位置から位相を決めれば
（`phase = x/3 + y/3`）、4辺の枠が1枚の箔から切り出したように見える。

### 9.7.2.1 EXTRA だけは構造を変える（放射プリズム）

**EXTRA を「HARD の量を増やしただけ」にしない。** 同じ発想の延長だと
最高位に見えない。EXTRA だけ**構造そのもの**を変える。

```
┌──────────────┐
│ INTELLIGENCE │  ← カテゴリ帯（光線より前面）
├──────────────┤
│ \  ╲ │ ╱  / │
│  \ ╲███╱ /  │  ← 光線がスプライトの背後から放射
│ ───█████─── │
│  / ╱███╲ \  │
├══════════════┤  ← ここで硬く切る
│ 単語を30個     │  ← 名前帯（べた塗り・明るい文字）
│ ♦♦      10XP  │
└──────────────┘
```

- **上半分 = 絵、下半分 = 名前帯。** シールの構造そのもの。
  文字は `color/panel` のべた塗りの板に載せ、`ink` / `points` で明るくする
- 光線は**角度で色相を決める**（`sector = floor(角度 × 本数)`）。
  一本おきに抜くと光線になる。中心の半径4ドットは空けてスプライトを置く
- **光線は回転させない。** ピクセルを回転すると格子が崩れる。
  **位相をずらした2コマを `HOLD` で交互に見せる**（コマ送り）
- カテゴリ帯は光線より前面に置く。背面にすると帯とカテゴリ名が潰れる

### 9.7.2.2 EXTRA の素材 = プラチナで確定（2026-09-05）

同じ「放射プリズム + 名前帯」の構造で素材だけが違う2案を作り、**案B（プラチナ）を採用**した。
虹は暖色の地に対して強すぎ、案Bの方が世界観に馴染むため。
（比較用の `RARITY — 4段階の比較` は Figma に残してある）

| | 案A `Rarity-Extra`（虹） | 案B `Rarity-Extra-Platinum`（プラチナ） |
|---|---|---|
| 色 | 彩度のある虹7色 | 明暗6段の寒色ランプ（`color/plat/*`） |
| 印象 | 派手・お祭り的。ビックリマンに近い | 落ち着いた高級感。金属的 |
| 世界観との相性 | 暖色の地に対して**異物として強い** | 暖色の地に馴染む。ただし**冷たい** |
| 他レベルとの連続性 | NORMAL の淡い箔 → HARD の虹 → EXTRA の虹、と繋がる | EXTRA だけ素材が飛ぶ |

**金属をピクセルで見せる要点**（案B）
- **色相ではなく明暗で見せる。** 階調を**不均等**にして、
  明るい段と暗い段を隣り合わせると光沢になる。
  等間隔の階調にすると、ただの灰色になる
- ランプは `[spec, 1, 2, 4, 5, 4, 2, 1]` のように**山と谷**を作る
- わずかに寒色に振るとプラチナ、暖色に振ると銀や金になる
- **暗い下地を敷く**（`plat/base`）。光線の隙間からカード面の色が
  透けると金属が濁る
- **斜めの反射光**（`plat/streak`）が金属らしさの決め手。
  45度なので階段は1ドットずつ

**残っている不整合**: EXTRA をプラチナにしたが **HARD はまだ虹のまま**。
20枚を並べると **HARD が EXTRA より派手に見え、レア度の序列が逆転している**。
素材の階段を「淡い箔 → 銀 → プラチナ」に揃えるのが自然（未対応）。

### 9.7.3 実装上の要点

- **箔の上のスプライトは暗いシルエットにする**（`ink/outline`）。
  明るいスプライトは虹色に埋もれて消える
- **ループさせる箔は、切り抜き枠 + 1周期分widerな柄**で作る。
  枠に `clipsContent`、中の柄を `-63px` まで `HOLD` で送る
- ハイライトは**柄と別レイヤー**にして動かさない
- **暗い枠の上ではスプライトを明るく、箔の上では暗く。** 地が変わったら必ず見直す
- 生成した縞と光線は**ノード数が多い**（EXTRA の光線2コマで約420）。
  Figma では SVG から一括生成しているが、**コードでは繰り返し背景か
  1枚の SVG にする**こと。DOM に400ノード置かない

### 9.7.3.1 20バリアントの作り方

`TaskCard/Pixel` は **Category 5 × Level 4 = 20バリアント**。

**箔の部品はカテゴリに依存しないので共有する。** 特に EXTRA の光線は
1枚あたり209ベクタあるため、5枚が個別に持つと 2000ノードを超える。
`Plat/RaysA` などのコンポーネントにして**インスタンスで置く**こと。

| 部品 | 使う Level | 中身 |
|---|---|---|
| `Plat/RaysA` / `Plat/RaysB` | EXTRA | 位相違いの放射光2コマ |
| `Plat/Streak` | EXTRA | 斜めの反射光 |
| `Plat/Frame` | EXTRA | 2ドット厚の金属枠 |
| `Foil/FrameRainbow` | HARD | 1ドット厚の虹枠 |
| `Foil/SlotRainbow` | HARD | スプライト枠の中の箔 |

**カテゴリごとに変わるのは**、面の色 / ベベル暗色 / カテゴリ帯 / ラベル /
スプライト / タイトル / XP / 所要時間 / 難易度のひし形。

### 9.7.4 未解決: カードが文字主体であること

シールは**絵が主で文字は名前だけ**だが、このタスクカードは
タイトル・所要時間・XP と**文字が多い**。そのため EXTRA でも
面全体を箔にできず、スプライト周りの帯に留めている。

高レア度で**絵を大きく・文字を少なくするレイアウト**に組み替えるかは未決。
組み替えるなら、文字はべた塗りの板（シールの名前帯）に載せる。

### 10.3 オーバーレイの見せ方

ピクセル調を保つため、以下を守る:

- **背景の暗幕に blur をかけない**。`--scrim`（黒 70%）のベタ塗りのみ
- モーダルは 3px 輪郭 + ベベル（§4.1）。角丸なし
- 出現は**下からせり上がる**。`EASE_OUT_BACK` で軽く行き過ぎてから収まる
- 閉じるときは逆再生でよい（`EASE_IN`）
- **フェードで薄く消さない**。透明度を使うなら `HOLD` で一段階（§8.1）

### 10.4 オーバーレイの中身

**`Overlay/Detail`（Source: List = 354×540 / Today = 354×468）**

| 位置 | 要素 |
|---|---|
| (3, 6) 348×42 | カテゴリ帯。`Overlay/Form` では金地の `NEW QUEST` / `EDIT QUEST` |
| (312, 12) 30×30 | 閉じる ✕ |
| (12, 66) | タイトル（heading-jp） |
| (12, 102) | 説明（body-jp） |
| (12, 190) | LEVEL チップ 4つ（78×42、pitch 84） |
| (12, 266) / (12, 314) | TASK TIME のステッパー（時間 / 分） |
| (12, 390) 330×60 | 主アクション（`List` のみ）／ 削除（`Today`） |
| (12, 462) 330×60 | 削除（`List` のみ） |

**削除はどの画面から開いても常にある。** カードは自分自身を削除する手段を
持つべきで、それが Today からしか使えないのは誤り（2026-09-05 に修正）。

フッターの構成:

| Source | 主アクション | 削除 |
|---|---|---|
| `List` | 「Today へ送る」金ボタン（y=390） | **常にある**（y=462） |
| `Today` | なし（完了はドラッグ） | **常にある**（y=390） |

- 主アクション → `PATCH /api/tasks/:id` `{ screen: "today" }`
- 削除 → `DELETE /api/tasks/:id`

**削除は必ずフッターの最下段**に置き、`delete/button` / `delete/text` という
同じ名前で持つ。位置は主アクションの有無でずれるが、
「最後の要素が削除」という関係は変わらない。

**所要時間はスライダーではなくステッパー**（◀ 値 ▶）。
現行コードは Days / Hours / Min の3スライダーだが、つまみのある
スライダーはピクセル調に合わない。RPGメニュー風のステッパーに置き換える。
**Days は廃止**し 時間 / 分 の2軸にした（1日を超えるタスクは日次アプリの
想定外のため）。`estimatedMinutes` の型は変わらない。

**削除の導線をここに置いた理由**: `DELETE /api/tasks/:id` は実装済みだが
UI が無かった（`docs/ai-product-brief.md` §7）。タスクの詳細は、そのタスクに
対してできることが集まる場所なので、削除もここに属する。
押し間違いを避けるため、ベベルを付けず「押したくなる見た目」にしていない。

**`Overlay/Form`（354×636、Mode: Create / Edit）**

作成と編集は骨格が同じなので1つのコンポーネントにまとめた。
詳細（`Overlay/Detail`）との違いは次の3点。

- ヘッダーが金地（`NEW QUEST` / `EDIT QUEST`）
- タイトル / メモが入力欄（`--field` 塗り + 3px 輪郭）
- **CATEGORY の選択行**（60×48 のアイコンボタン5つ、pitch 66）

| Mode | 中身 | フッター | API |
|---|---|---|---|
| `Create` | プレースホルダー表示 | 「クエストを追加」 | `POST /api/tasks` |
| `Edit` | 既存の値が入った状態 | 「保存する」 | `PATCH /api/tasks/:id` |

**取り消しはヘッダーの ✕。** キャンセル用のボタンは置かない
（✕ が既にその役割を持っているため、2つあると迷う）。

**編集中は削除を出さない。** 削除は詳細（`Overlay/Detail`）に戻ってから行う。
編集の途中で破壊的操作が並ぶと押し間違いが起きやすいため。

### 10.4.1 閲覧と編集の関係

タスクの詳細は **閲覧** と **編集** の2段階に分かれる。

```
一覧の行 / Todayのカードをタップ
        ↓
  Overlay/Detail（閲覧）
   ├ Level・所要時間はここで直接変更できる
   ├ ✎ ボタン ────→ Overlay/Form (Mode=Edit)
   │                    └ 保存する / ✕ で詳細へ戻る
   ├ Today へ送る（List のときだけ）
   └ 削除する
```

**Level と所要時間だけは閲覧の状態から直接変更できる**（チップとステッパー）。
値を選ぶだけで文字入力を伴わないため、編集モードに入る必要がない。
**タイトル・メモ・カテゴリの変更には編集モードが要る。**

`Overlay/Detail` のヘッダーには ✎（276, 12）と ✕（312, 12）が並ぶ。

### 10.5 エントリポイント

| 操作 | 場所 | 開くもの |
|---|---|---|
| ＋ ボタン | HOME 上部バー (288, 52) 36×36 | `Overlay/Form` (Mode=Create) |
| カードをタップ | HOME のカルーセル中央 | `Overlay/Detail` (Source=Today) |
| 行をタップ | 一覧3画面 | `Overlay/Detail` (Source=List) |
| ✎ ボタン | 詳細のヘッダー (276, 12) 30×30 | `Overlay/Form` (Mode=Edit) |

**ドラッグ操作は Today のカードだけに使う。** 一覧では使わない
（世界観に合わないため。決定: 2026-09-05）。

既存の `TaskCarousel.tsx` は framer-motion の `drag` とスプリングを自前調整済みなので、
